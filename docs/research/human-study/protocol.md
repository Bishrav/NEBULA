## Research question

For engineering-documentation tasks, does an evidence-aware retrieval interface change task success, time to a useful source, verification behavior, or confidence compared with a conventional hybrid search interface?

This is a secondary human-evaluation track. The primary NEBULA contribution remains offline empirical retrieval evaluation.

## Design

Proposed exploratory, within-participant comparison with counterbalanced condition order:

- Condition A: conventional hybrid retrieval with ordinary result metadata.
- Condition B: NEBULA retrieval with score decomposition, source metadata, freshness/authority signals, and evidence preview.
- Each participant completes the same three task categories using a fixed synthetic/public-safe corpus.
- The interface condition is the independent variable; task outcomes are exploratory dependent variables.
- Target pilot size: 5–10 participants, explicitly not powered for population-level inference.
- Session duration: approximately 30 minutes, including briefing and debriefing.

The final sample, eligibility, compensation, and condition order require institutional approval.

## Eligibility

Proposed inclusion: adults meeting the institution's minimum age who regularly search technical engineering documentation as part of study or work.

Proposed exclusion: inability to give informed consent, inability to complete the approved language version, or prior direct involvement in designing the study tasks if that creates a conflict. The reviewer must approve the final criteria.

## Measures

Primary exploratory outcomes:

1. Task success under the pre-specified task rubric.
2. Time from first query to first useful, verifiable source.
3. Verification behavior: opening evidence, checking source metadata, and explaining acceptance/rejection.

Secondary outcomes:

- query reformulations;
- zero-result searches;
- usefulness feedback;
- confidence from 1 (not confident) to 5 (very confident);
- explanation inspection and perceived cognitive load.

No productivity, employment, performance-review, or professional-competence claim will be made.

## Procedure

1. Confirm eligibility and provide the approved information sheet.
2. Answer questions and obtain documented consent before telemetry is enabled.
3. Start a fresh session using a random study code unrelated to identity.
4. Present one task at a time using the approved task script.
5. Counterbalance condition order according to the pre-generated schedule.
6. Record only approved telemetry and the participant's voluntary questionnaire responses.
7. End telemetry, provide the debriefing, and explain withdrawal contact.

## Stopping and incident rules

Stop the session if consent is withdrawn, the participant becomes distressed, private or workplace data is entered, the system records data before consent, or the approved privacy boundary is breached. Preserve the incident record separately and notify the responsible reviewer according to institutional policy.

## Claims boundary

The pilot is exploratory and convenience-sampled. It cannot establish population-level usability, causal user benefit, product-market fit, or superiority of NEBULA without a larger approved design.
