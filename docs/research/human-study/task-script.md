# Participant task script

**DRAFT — REQUIRES INSTITUTIONAL/SUPERVISOR REVIEW**

## Facilitator rules

- Use the approved wording without coaching query terms.
- Do not reveal the expected document, ranking condition, or correct answer.
- Give the same task order or approved counterbalanced order to every participant.
- Ask participants to use the system as they normally would.
- Record only the approved task events; keep observer notes separate.

## Task set

The final task wording must be frozen against the admitted corpus and reviewed for answerability.

| Task ID | Information need | Category | Success rubric |
| --- | --- | --- | --- |
| T1 | Identify and verify an appropriate operational source for recovering after a deployment rollback failure. | deployment/failure recovery | source is relevant and participant explains one supporting piece of evidence |
| T2 | Find documentation that helps diagnose a distributed shard or replica failure. | debugging/distributed systems | source is relevant and participant identifies a recovery-relevant detail |
| T3 | Compare two technical sources and explain which one should be trusted for the scenario and why. | verification/architecture | participant cites evidence, version/freshness, or source context rather than popularity alone |

## Per-task script

1. Read the task exactly as approved.
2. Start the task timer and task event.
3. Allow queries, reformulations, result opening, evidence inspection, and normal navigation.
4. Do not answer technical questions or suggest search terms.
5. Stop when the participant identifies a source and explains why it addresses the need, or at the approved time limit.
6. Record success according to the rubric, not from clicks alone.
7. Ask confidence from 1 to 5 and the approved short explanation question.

## Debrief guardrail

Do not reveal the condition order or explain ranking implementation until all tasks and post-task questions are complete.
